# Audio ports of every plugin in plugin-manifest.txt, as LV2 declares them:
# inputs, outputs, URI. Read by the rig compiler (tool/src/sushi_rig/stereo.py).
#
# Why the compiler needs them: Sushi 1.3.0 gives a plugin on a track
# min(its ports, the track's channels) of each, and clears every channel a
# plugin did not write (track.cpp `_process_plugins`). So a plugin with one
# output on a stereo track silences the right channel from there on, bypassed
# or not; measured for every one-output plugin below (tests/test_stereo.py,
# CI, 2026-11-02). After each such plugin the compiler inserts its copy to
# stereo. Sushi reports no channel counts itself (neither --dump-plugins nor
# gRPC's ProcessorInfo), so they are kept here.
#
# Written from lilv 0.24.22 over Ubuntu 24.04's packages, the ones CI's image
# installs. CI checks every line against lilv over plugins/ (tests/test_stereo.py
# `test_the_port_table_is_what_lilv_reads`), so a package update that changes a
# plugin's ports fails the build rather than the right channel.
#
# Not here: the neural amp (http://github.com/mikeoliphant/neural-amp-modeler-lv2).
# It runs in Carla, never on a Sushi track, no distro packages it, and CI's
# image cannot read its ports; a rig that put it on a chain is refused by name.
#
# To add a plugin: `sushi-rig probe <uri>` prints "audio N in / M out"; add
# "N M <uri>" here, beside its line in plugin-manifest.txt.
